# event loop

Собрано в одно место из трёх заметок, которые пересказывали одно и то же: `node-js-event-loop`, `browser-event-loop` и карточки в [nodejs interview](/doc/nodejs-interview).

## Кто что делает

| | |
| --- | --- |
| **V8** | интерпретирует JS в байт-код, JIT-компилирует горячие участки в машинный код |
| **libuv** | сам цикл + асинхронный I/O у ОС (fs, сокеты) + абстракция над epoll / kqueue / IOCP / event ports |
| **thread pool libuv** | **4 потока по умолчанию**, и ими пользуются только **fs, crypto, zlib и DNS-резолв**. Всё остальное - в основном потоке |

Отсюда практический вывод: «Node однопоточный» неверно. Неверно и «всё асинхронное уходит в пул» - туда уходят четыре вида операций, остальное отдаёт ОС.

## Фазы, один оборот = tick

Семь фаз, каждая - FIFO-очередь колбеков. Войдя в фазу, цикл выполняет её очередь, пока та не опустеет либо не упрётся в лимит, потом идёт дальше.

| # | фаза | что здесь |
| --- | --- | --- |
| 1 | **timers** | `setTimeout`, `setInterval` |
| 2 | pending callbacks | отложенные системные колбеки |
| 3 | idle | в Node не используется |
| 4 | prepare | в Node не используется |
| 5 | **poll** | ожидание и приём I/O |
| 6 | **check** | `setImmediate` |
| 7 | close callbacks | `close`-события сокетов и хендлов |

Таймер задаёт **порог, после которого колбек может быть выполнен**, а не точный момент. Отсюда `setTimeout(fn, 0)` не значит «сейчас».

## Микро против макро

**Микрозадачи** - промисы, `process.nextTick`, MutationObserver в браузере. **Макрозадачи** - `setTimeout`, `setInterval`, `setImmediate`, асинхронный I/O, DOM-обработчики.

Очередь микрозадач выгребается **после каждого колбека и в конце каждой задачи**, пока никакой JS не выполняется в середине. Микрозадачи, поставленные во время разбора микрозадач, добавляются в хвост той же очереди и тоже выполняются - до перехода к следующей макрозадаче. В спецификации ECMAScript микрозадачи называются **jobs**.

Канонический пример, порядок вывода:

```js
console.log('script start')
setTimeout(() => console.log('setTimeout'), 0)
Promise.resolve()
  .then(() => console.log('promise1'))
  .then(() => console.log('promise2'))
console.log('script end')
```

```
script start · script end · promise1 · promise2 · setTimeout
```

`script end` - часть первой задачи. Промисы уже разрешены, но их колбеки уходят в микроочередь и ждут конца текущего скрипта. `setTimeout` - отдельная задача, поэтому последний.

## В браузере

У каждого потока свой цикл: каждый web worker получает собственный и работает независимо; все окна одного origin делят один цикл, потому что могут общаться синхронно.

У цикла несколько **источников задач**. Порядок внутри одного источника гарантирован, но браузер сам выбирает, из какого источника взять задачу на этом обороте - так он отдаёт приоритет чувствительному к отклику, например пользовательскому вводу. Между задачами браузер **может** отрисовать кадр; между микрозадачами - нет.
